# OpenMV 单核下视水平视觉里程计

320×240 灰度图，MicroPython 负责采图、通信和状态管理，原生 `rm_vo` 负责视觉计算。正常目标 **24 点**，至少两个可靠内点可继续跟踪。姿态来自飞控、高度来自 ToF，视觉解算 N/E 水平位置。

**本版接口为 ABI 3，需要重编包含 `rm_vo` 的固件，并配套更新 Python 文件。**仅复制 Python 文件到原版 OpenMV 4.5.9 固件不能运行。

## 算法流程

1. 对齐图像、飞控姿态与 ToF 时间，补偿倾角和传感器安装位置。
2. 初始化用纯 FAST-9 找点；正常用 8×8 KLT 跟踪并做反向检查，失败点只在 6～8 px 内搜索。
3. KLT、补救搜索和少点歧义检查统一消除图块亮度偏移；不做整图亮度归一化。
4. 将匹配点投影到地面，筛选支持同一水平位移的严格多数，再加权求解。两个点必须一致。
5. 每帧只选一个参考进行完整跟踪：通常为前一有效帧，每五帧选择关键帧。低于18点时限量补点，每帧最多扫描六格、增加四点。
6. 更新真实位置和唯一置信度。短暂匹配失败进入运动预测，超时后失跟，持续失败后重建原点。

保留标定、姿态、高度、安装偏移和必要模板变形补偿。移除 ORB、视觉偏航拟合和随机 RANSAC；复用参考地面坐标及局部变换，平移候选验证预计算固定投影系数并提前淘汰无望候选。方法来源见 [native/SOURCES.md](native/SOURCES.md)。

## 参数调整

统一修改 [config.py](config.py)，关键参数均有单位、作用和调整影响注释。

| 参数 | 默认值 | 作用 |
|---|---:|---|
| `MAX_KEYPOINTS` | 24 | 正常特征目标；原生容量64，最低两点 |
| `CONFIDENCE_SIGMA0_M` | 0.05 m | 位置标准差达到此值时方差项半分；调大使同等方差的评分更高 |
| `CONFIDENCE_FULL_POINTS` | 16 | 可靠内点达到16后，点数项满分 |
| `CONFIDENCE_FULL_CELLS` | 6 | 3×3网格覆盖六格后，覆盖项满分 |
| `TRACK_HOLD_US` | 1000000 μs | 最后真实成功后最多预测1秒；调大容忍更长遮挡，也增加漂移 |
| `LOST_RESET_US` | 3000000 μs | 最后真实成功后持续未恢复3秒，重建原点；必须大于预测窗口 |
| `PREDICTION_HISTORY_SIZE` | 5 | 用于拟合匀速的最近真实成功结果数量 |
| `PREDICTION_VELOCITY_STD_M_S` | 0.5 m/s | 速度不确定度下限；调大使预测方差增长更快 |
| `TRANSLATION_GATE_PX` | 2.5 px | 位移一致性的重投影门槛，调大更宽松 |

唯一置信度：`Q = 100 × (0.70V + 0.10N + 0.10C + 0.10M)`，各分量限制在0～1。

- `V = sigma0² / (sigma0² + max(方差N, 方差E))`。
- `N = min(可靠内点数 / 16, 1)`；`C = min(覆盖格数 / 6, 1)`，分母由上表参数控制。
- `M = 内点比例 × 内点平均匹配权重`；权重同时考虑去亮度偏移的窗口误差和反向误差。

少点不再设置20/30分封顶，通过保守方差体现不确定性。姿态、高度、时序和未知外参误差计入方差；公共误差不按点数平均消除。置信度是工程评分，不是正确概率。

## 预测与失跟

最近五次真实成功的位置按实际时间拟合速度：`预测位置 = 最后真实位置 + 估计速度 × 间隔`。历史不足两次时保持最后位置。预测结果不反馈进历史。

- 距最后真实成功 **≤1秒**：输出“短时预测”，继续尝试匹配；方差随时间及速度不确定度增长，置信度随之降低。恢复真实匹配后立即续接。
- **>1秒且<3秒**：位置无效，保留参考尝试恢复；恢复后连续三帧确认。
- **≥3秒**：显式重建原点并增加 `reset_counter`；两个期限始终从最后真实成功计时。
- 初始化同样需要三帧确认。飞控重启、时钟跳变和姿态重置另行清除旧轨迹。

结果的 `timestamp_us` 对应本帧/预测时刻，`measurement_timestamp_us` 保留最后真实测量时刻；`predicted`、`measured` 明确区分预测与测量。预测帧单列统计，不计入真实定位成功率，不作为新的视觉测量发布到飞控。

## 运行与调试

板上更新 `config.py`、`algorithm.py`、`control.py`、`comm.py`、`output.py`、`main.py`；需要调试时另放入 `test.py`。

- 正常入口：`main.py`，限频显示状态、N/E、高度、姿态、FPS和置信度。
- 调试入口：`test.py`，`MODE=1`轻量观察与总结；`MODE=2`增加阶段计时，退出后保存日志，运行中不写文件。
- 两种调试摘要均显示状态、ΔN/ΔE、高度、横滚/俯仰/航向（度，保留一位小数）、处理FPS、可发布Hz和有效率。仅状态变化或按q时输出；状态变化摘要最小间隔1秒，q立即查询，姿态角变化不单独触发。姿态缺失或数据过期显示`--`。
- 原始USB终端按键：Enter在下一次真实有效测量建立显示原点；q查询；x结束。版本为 `sparse-vo-3`。IDE主调试连接需先断开。
- Enter仅打印原点建立或等待提示，不额外触发完整摘要；稳定状态不定时刷新。
- 真实稳定追踪、短时预测、失跟分别统计；“可发布”仅模拟准入，测试始终不发ODOMETRY。

默认 `SEND_ODOMETRY=False`。实际融合前需确认相机方向、安装位置和传感器时序。输出只提供水平位置观测；飞控姿态和 ToF 高度不重复包装成独立视觉观测。

保留单采集缓冲，当前图加两幅独立参考图共225 KiB，另计Python堆和工作区。原生调用不逐帧分配，正常入口不启用详细原生计时。实际上下文大小以 `rm_vo.CONTEXT_BYTES` 为准。

## 构建与验证

OpenMV v4.5.9源码放在本项目内部，从 `visual_odometry` 目录执行：

```sh
python3 -B native/prepare_openmv.py native/_build/openmv
cd native/_build/openmv/src
make -j4 TARGET=OPENMV4P
```

`OPENMV4P` 对应官方H7 Plus，请按实际板型选择。固件安装后检查 `rm_vo.ABI_VERSION == 3`。通用Make/CMake接入文件位于 `native/`。

PC回归使用真实C核心和GCC：

```sh
python -B native/verify.py
# 可选：另验实际MicroPython绑定
python -B native/verify.py --micropython <包含ABI3模块的MicroPython可执行文件>
```

检查已知位移、补偿、少点拒绝、亮度偏移、评分、预测衔接、时间边界、发布与统计。PC检查不代表板上FPS；板上仍需对照静止漂移、已知运动、遮挡恢复、真实定位率和最低可用堆。
