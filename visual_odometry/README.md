# OpenMV 单核下视水平视觉里程计

固定使用 **320×240 灰度图**，不设目标 FPS。MicroPython 负责采图、飞控通信和状态管理，原生 `rm_vo` 模块负责主要视觉计算。N/E 由图像解算，姿态来自飞控，高度来自 MTF-02P ToF；ToF 模块的光流不参与视觉匹配。

**本版需要包含 rm_vo 的自编译固件。仅复制 Python 文件到原来的 4.5.9 固件不能运行。**缺模块时会直接提示编译安装方法，不会自动切回旧算法。

## 文件与入口

| 文件 | 职责 |
|---|---|
| `config.py` | 已标定内参、安装外参、曝光、串口、跟踪与输出参数 |
| `algorithm.py` | 姿态运算、紧凑原生接口、原生阶段计时读取 |
| `control.py` | 输入时间对齐、ToF 高度、状态恢复、质量与方差、显式重置 |
| `comm.py` | MAVLink、飞控发现、同步、固定容量历史环与最新观测发送 |
| `main.py` | QVGA 采图、曝光控制、单核主循环和实际 FPS |
| `output.py` | 一行摘要与独立 ODOMETRY 发布准入 |
| `test.py` | 事件触发摘要、手动初始点；MODE2全程统计和退出日志 |
| `native/vo_core.c/.h` | 可移植 C99 核心；无相机、UART、MicroPython 或堆分配依赖 |
| `native/modvo.c` | MicroPython 缓冲协议绑定，模块名 `rm_vo` |
| `native/prepare_openmv.py` | OpenMV 4.5.9 STM32 固件接入 |
| `native/verify.py` | 使用真实 C 核心的简要 PC 合成检查 |
| `verify_logging.py` | PC检查按键、初始点、准入、少点统计和退出日志，无需板卡 |
| `native/vo_fast.c/.h` | OpenMV 4.5.9 FAST-9原生判定树的无分配适配，保留原BSD许可 |

板上同时替换七个 Python 文件。正常入口为 `main.py`；测试入口为 `test.py`。不要混用旧接口。

## 算法与运行行为

1. 将图像时刻对应到飞控时钟，插值姿态；ToF在测量时刻做倾角和安装偏移补偿，再对齐图像。
2. 正常目标保持48点、原生容量64。纯FAST-9检测，无ORB描述子。首张初始化图扫描完整6×4网格，之后检测和补点限流；少点不因未达到48而失败。
3. 保留姿态、畸变、高度、安装位置补偿及搜索位置预测。相对旋转超过约1度或高度变化超过2%时才重采样局部仿射模板。
4. 8×8逆组合KLT预计算模板梯度和矩阵，保留12轮上限、亚像素和反向检查。失败点仅在6～8px半径内做有限SAD；比较独立匹配峰，取消40px扩搜、多轮全参考重试和ORB恢复。
5. 将对应点投影到地面，确定性位移一致性筛选后加权解算N/E平移。飞控提供旋转，不再拟合视觉残余偏航或执行随机RANSAC。点分布进入质量评分，不以二维铺开作为平移解算硬门槛。
6. 每帧最多一轮完整跟踪；正常使用前一有效帧，每5帧选择固定关键帧，初始参考相同则合并。跟踪点低于目标75%时，每帧最多扫描6个缺点网格、新增4点，并轮转覆盖。
7. 两三个可靠内点可维持有效的少点跟踪，需反向误差、位移一致性和额外去亮度偏移的匹配歧义检查通过。两点冲突、单点、无点或无效输入均不输出有效位置。初始/失跟恢复保持3帧确认；正常与少点切换不清原点、不重走确认。
8. 双点质量上限20，三点上限30；随机测量方差分别放大4/2倍并保留像素误差下限。姿态、测距和时序公共误差不按点数消除。关键帧与相邻帧方差沿参考链传播。
9. 失败不提交参考或位置；清除不可靠搜索速度，保留旧参考作有限恢复。连续视觉失败2秒后显式重置原点并增加reset_counter。大位移重识别能力较旧版下降。关键帧失效后，等下一次相邻帧真实测量成功再续接新关键帧，避免每隔5帧重复遇到同一失效锚点。
10. 有效结果使用原图时间戳、去重发送；显示与发布独立。少点仍计有效跟踪，但默认质量门槛40使其不发布到飞控。

相机安装臂长参与地面投影。固定关键帧减轻局部漂移；持续换帧仍有里程计漂移。平面和姿态辅助条件不成立时，降低质量不能使错误观测变得有效。

四个项目的具体参考入口与实现边界见 [native/SOURCES.md](native/SOURCES.md)。

## 参数变化

| 参数 | 默认与含义 |
|---|---|
| 图像 | 320×240 GRAYSCALE，已删除缩图与目标 FPS 配置及其依赖 |
| `MAX_KEYPOINTS` | 48，容量64；实际点数不足时可降级跟踪 |
| `FAST_THRESHOLD` | 15，纯FAST-9灰度差阈值，不调用find_keypoints |
| `KLT_MAX_ITERATIONS` / `KLT_MAX_ERROR` | 12 / 15，梯度与矩阵预计算，去亮度偏移的RMS误差 |
| `KLT_FB_ERROR_PX` | 1.5px，少点同样执行正反向检查 |
| `SEARCH_MIN_PX` / `SEARCH_MAX_PX` | 6 / 8px，围绕预测位置的残差搜索半径 |
| `SAD_UNIQUENESS_RATIO` | 0.90，最佳代价须优于独立候选峰 |
| `MIN_MATCHES` / `MIN_INLIERS` | 2 / 2；同时要求严格多数和比例至少0.55 |
| `FEATURE_TOPUP_CELLS` / `FEATURE_TOPUP_POINTS` | 6 / 4，每帧补点预算 |
| `KEYFRAME_CHECK_INTERVAL` | 5帧，每帧仅一个完整主参考，不额外全量重试 |
| `TEMPLATE_WARP_ANGLE_RAD` / `TEMPLATE_WARP_HEIGHT_RATIO` | 约1度 / 2%，超过时重采样模板 |
| `RANSAC_THRESHOLD_PX` | 保留配置名，2.5px；现在用于确定性平移拟合，不再有RANSAC |
| `LOST_RESET_US` | 2,000,000us，真正持续失跟后显式重置 |
| `ATTITUDE_HZ` / `RANGE_HZ` | 50 / 30Hz，独立MAVLink请求目标 |
| `ATTITUDE_WAIT_US` / `SYNC_SERVICE_US` | 2,000 / 6,000us；初次同步允许30,000us窗口 |
| `EXPOSURE_MIN_US` / `EXPOSURE_MAX_US` | 300 / 12,000us，保留低频亮度和模糊控制 |

32位/64位缓冲接口已升级为 **ABI 2**：配置33项float32，结果31项float32，图像时刻仍为两项uint32，六阶段计时为六项uint32。正常运行不启用原生时钟采样；仅MODE2启用。

## 图像所有权与内存

| 区域 | 大小与生命周期 |
|---|---|
| 相机当前灰度图 | 76,800 字节 = 75 KiB；只在同步原生调用期间借用 |
| 原生关键帧图像 | 75 KiB，换关键帧时复制，期间保持原模板 |
| 原生前一有效帧图像 | 75 KiB，每次接受视觉解后复制当前帧 |
| 特征、元数据、匹配与窗口工作区 | PC 64 位构建为 5,760 字节，板上以 `rm_vo.CONTEXT_BYTES` 为准 |
| 原生 context 合计 | PC 构建 159,360 字节；无逐帧 C 分配 |
| 姿态、ToF、高度缓存 | 每类固定容量 100 的历史环；Python元组另计；不再保留ORB描述子 |

总的三幅图像为 225 KiB，不含相机驱动、IDE 预览、Python堆。新增梯度工作区512字节按点复用，没有完整梯度图；固定上下文比旧版增加888字节，删除ORB减少的Python临时内存需板上测量。Python 使用复用的 float32 输入/输出数组，64 位时间戳通过两项 uint32 传入，不经浮点转换。

**4.5.9 默认保留单个采集缓冲。**其公开接口没有逐缓冲曝光时间标识，不能用“最新回调时间”去标记可能更旧的排队图像，因此本版没有启用多缓冲采集/计算重叠。`snapshot_return` 与可选的单缓冲 `frame_callback` 记录时刻仍需通过 `CAMERA_TIME_OFFSET_US` 标定到曝光中心；它们不是硬件曝光时间戳。原生参考有独立所有权，相机复用不会覆盖参考。

常规跟踪中不再每秒固定调用 GC；空闲堆低于 `GC_LOW_WATER_BYTES` 时主动回收，MicroPython 自身仍可能在分配时回收。

## 固件构建与部署

本版PC检查使用真实C核心、严格GCC编译和合成图像，验证FAST等价性、正常/少点跟踪、补偿、异常拒绝及Python状态和日志。并已将ABI 2模块编译进MicroPython 1.24.0 Windows运行时，实际验证64位时间戳、缓冲检查、阶段计时、Python前端及双点原生跟踪。**未连接OpenMV，未生成或刷入ARM firmware.bin，未测板上FPS。**PC数值结果不能替代板上验证。可用原生MicroPython运行时另行运行 `python -B native/verify.py --micropython <可执行文件>`。

请在 Linux/WSL 的 ARM 构建环境中，将 OpenMV **v4.5.9** 源码及其对应子模块放在本项目内部；Make 不善于处理带空格的绝对路径，构建时使用无空格的相对路径。下面从本项目目录开始：

```sh
git clone --branch v4.5.9 https://github.com/openmv/openmv.git native/_build/openmv
git -C native/_build/openmv submodule update --init --recursive
python3 -B native/prepare_openmv.py native/_build/openmv
cd native/_build/openmv/src
make -j4 TARGET=OPENMV4P
```

`OPENMV4P` 对应官方 H7 Plus；实际板型需与硬件匹配。准备脚本只允许修改本项目内部的源码树：复制模块到 `src/omv/rm_vo`，利用原构建的模块发现机制，同时将两个目标文件加入 STM32 最终链接。脚本可重复运行。

完成后用 OpenMV IDE 加载所构建的固件。先在 REPL 检查：

```python
import rm_vo
print(rm_vo.ABI_VERSION, rm_vo.CONTEXT_BYTES)
```

应能导入且 ABI 为 2，再将七个 Python 文件复制到板上运行。通用 MicroPython Make / CMake 接入文件也位于 `native/`，供后续移植使用。自研 H7 需要 `vo_core.c/.h`、`vo_fast.c/.h` 与自己的图像、传感器、存储调度；DMA 缓冲需由板级工程正确处理存储区域和缓存一致性。

## 默认输出与飞控融合

```text
状态=跟踪正常（近似） | N=+0.123 E=-0.045 m | 高度=0.803 m | 横滚/俯仰/航向=+1.2/-0.8/+32.5 度 | FPS=19.0 | 质量=35/100
```

N/E 的零点由初始化建立，单位米；质量综合内点数量、比例、空间分布、残差及高度新鲜度。IDE 显示不依赖 `SEND_ODOMETRY`。失跟时显示“位置=无效”。

相机系 C 为图像右/下/光轴前，机体系 B 为前/右/下，位置在 NED。保留标定内参和五项畸变系数，默认安装画面上方对应机头。以下项目仍需实测填写：

```python
CAMERA_POS_B_M = None
TOF_POS_B_M = None
CAMERA_ORIENTATION_CONFIRMED = False
SENSOR_TIMING_CONFIRMED = False
```

允许共点近似时可显示位置，标“近似”、质量上限 35；未确认的安装和时序不发布有效 ODOMETRY。默认 `SEND_ODOMETRY=False`。回传仅融合水平位置，保留时间戳、方差和重置计数；飞控姿态和 ToF 高度不重复包装成独立视觉观测。ODOMETRY 仍为 LOCAL_NED，z 为大方差的有限零占位，姿态及速度为 NaN；飞控融合配置须另行核对。

串口继续默认 UART3 / 115200，使用原有 GPS2 链路配置，不改飞控模式、EKF 参数或解锁状态。输入必须来自近似水平且静止的地面，单点 ToF 不能描述台阶或坡面。

## 轻量定位调试

test.py 顶部选择 MODE=1 或 MODE=2。两种模式持续运行，不自动限时退出，始终禁止发送 ODOMETRY。当前调试版本为 **sparse-vo-2**，原生rm_vo为 **ABI 2**；必须重新编译固件并配套更新Python文件。

| 模式 | 运行时 | 退出时 |
|---|---|---|
| MODE1 | 简短状态、相对位置、高度、处理FPS、可发布Hz、有效率；基本计数及原因计数 | 在终端打印统一总结和主要失跟原因；不生成文件 |
| MODE2 | 同样摘要；额外采集必要性能和故障指标，维护16条数值事件环 | 在终端打印统一总结，并创建UTF-8精简日志 |

状态变化触发摘要，自动摘要最多每秒一次；q可立即查询。稳定状态下不定时刷屏，位置或帧率变化本身不触发打印。摘要不展开失败原因，不显示姿态角或有效定位Hz；仅MODE2最终文件额外保留有效定位Hz。

### 输入与按键

使用原始USB串口终端。IDE主调试连接启用时脚本会报错，不读取IDE调试协议字节。可以停止并断开IDE主连接，再使用“工具→打开终端→串口”或其他原始终端；同一串口仅由一个连接占用，不使用1200波特率。

更新板上的Python文件后软复位，再进入REPL：

~~~python
import test
print(test.DEBUG_VERSION)  # 应为sparse-vo-2
test.MODE = 1              # 或2
# test.LOG_DIRECTORY = '/sd/logs'
test.main()
~~~

输入仍使用64字节复用缓冲，q/x无需追加回车，CRLF只算一次Enter。仅在电脑编辑器保存不会更新板上文件；可用 `test.__file__` 确认实际导入路径。

- **Enter**：在下一张新鲜、有效的新图像上建立/更新显示原点；无效时保留请求。
- **q**：查询当前摘要，不归零、不清空统计。
- **x**：结束，打印总结；MODE2随后保存文件。
- **Ctrl+C**：可捕获中断会尝试总结和保存；程序异常保留原异常，同时记录错误信息。

Enter只更新ΔN/ΔE参考，并重新开始屏幕2秒统计窗口，不改变视觉轨迹或全程计数。算法轨迹重置会清除旧原点，需重新按Enter。不再维护或写入原点区间的坐标分布统计。

摘要示例（示意值）：

~~~text
状态=跟踪正常（近似） | ΔN=+0.123m ΔE=-0.045m | 高度=0.803m | 处理=10.00FPS | 可发布=0.00Hz | 有效率=60.0%
~~~

ΔN/ΔE沿飞控姿态所在NED轴，相对按Enter时的位置；轴方向准确性仍依赖姿态和安装标定。未建原点、位置无效或观测过期时显示“--”。首个2秒窗口或Enter后窗口尚未完成时显示0并标“窗口统计中”。

### 统一最终总结与统计口径

| 项目 | 定义 |
|---|---|
| 总接收图像帧数 | 进入定位流程的新图像；包含初始化、输入不足及失跟帧，重复序号或重复/倒序时间戳不重复计数 |
| 稳定追踪帧数 | 现有 result.valid 为True，保持当前输入、几何和连续恢复确认判定 |
| 可发布帧数/平均Hz | 与正式Output共用时序、机体位置、质量、连接、同步、新鲜度、去重和限频检查；模拟通过数及该数量除以测量时长 |
| 平均置信度 | 稳定追踪帧的现有0～100质量评分均值；没有有效评分则显示“无有效样本”，不解释为准确率概率 |
| 平均处理FPS | 新图像总数除以测量时长 |
| 有效定位比例 | 稳定追踪帧数除以新图像总数 |
| 恢复与失效 | 失跟段数、轨迹重置次数、初始化/恢复确认帧数，以及主要原因前三项 |

测量从主循环首帧开始，到最后完成统计收尾的循环结束；包括等待、失跟、统计和终端输出，排除相机初始化、启动说明及最终总结/报告保存。若视觉调用在返回结果前异常中断，未完成循环不进入计数或耗时表；交互阶段异常则先完成已得到结果的统计收尾。

可发布只是干跑，不代表串口发送、飞控接收或融合频率，ODOMETRY实际发送始终为0。默认外参/时序未确认、近似质量上限35低于门槛40，因此有稳定位置时可发布仍可能为0；MODE2保留各受阻条件的帧数，不放宽门槛。

失跟段只从曾经有效追踪后转无效开始，到恢复有效结束，首次初始化不算失跟。原因按影响帧数统计，视觉/运行限制与输入不可用分组；初始化和恢复确认单列，不进入原因占比的分母。原生匹配不足、比例不足和歧义等原因明确统计；没有细分原因的LOST仍标“原因未细分”。少点有效结果计入稳定跟踪，单独累计少点帧数。若从未建立稳定追踪，总结列出首次定位受阻原因。

### MODE2保留项与内存

- 匹配数、内点数和像素残差的必要最低/平均/最大值；只在执行视觉时采样。
- 少点有效跟踪帧数；不再维护ORB恢复指标。
- 各主要失效原因、发布受阻条件的固定计数；同一帧可被多个发布条件阻止。
- 姿态和ToF接收总数/平均Hz、CRC错误及同步RTT拒绝计数的本次运行增量。
- 六项顶层阶段：采图/相机调节、通信/输入等待、视觉总处理、显式GC、调试统计/输入输出、完整循环。原生视觉再分补偿/窗口、KLT正反向、SAD、FAST补点、平移拟合和参考图复制六项；保留次数、平均/最大、累计耗时及占比。
- 可用堆每秒采样的最低值；不声称捕获瞬时分配峰值。GC只统计显式调用，自动GC耗时归入所在阶段。
- 关键启动配置、结束原因/错误，以及固定容量重要事件；不再采集姿态角、方差分布、搜索半径、KLT/SAD点数分布、原始ToF全程分布和完整结果字典。

计数使用固定表；只保存最新显示原点和结果，不保存图像或逐帧历史。事件环16条，每条载荷17字节，合计272字节，另有解释器对象开销；保存时间偏移、编号、参数及重复次数，相邻重复合并，覆盖旧记录时累计覆盖数。长时间运行仍保留全程计数，事件明细只代表保留的最近记录。阶段累计微秒使用整数，避免32位累计微秒约71分钟溢出。

原生六阶段是视觉子项，彼此不重复计时，也不再加进顶层耗时之和；少量调度、参考选择等开销仍留在视觉总耗时。原生次数表示有非零阶段耗时的帧数，并非角点调用次数；视觉总处理还包含输入状态判断和内部短轮询。调试统计的固定表更新计入调试/完整循环；完整循环还包含普通维护和发布检查等间隙，采图耗时含等待，不等于CPU占用。

### MODE2保存时机

测量期间不打开、写入或刷新日志文件，Enter不触发写盘。正常结束、可捕获中断或异常后，才选择 /sd/logs、/flash/logs 或PC的 ./logs；可用 LOG_DIRECTORY 指定现有父目录下的目录。文件按 vo_test_0001.txt 顺序编号，不覆盖旧文件。

报告逐段编码为UTF-8写入，不在内存中拼接完整报告。保存错误会显示失败或不完整，不能将其当作完成报告。**断电、硬复位或绕过finally的强制停止，会丢失未保存统计；该模式以消除运行中存储阻塞为优先。**
