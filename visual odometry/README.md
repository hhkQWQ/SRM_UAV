# OpenMV 下视水平视觉里程计

适用于当前 OpenMV H7 Plus / OV5640 / 固件 4.5.9、Pixhawk 6C Mini / PX4 1.17、下视 ToF 配置。OpenMV 独立使用相机解算 N/E 水平位移；姿态和测距由飞控通过 MAVLink 提供。ToF 的光流不参与本程序的视觉匹配。

## 文件与部署

| 文件 | 职责 |
|---|---|
| `config.py` | 标定、安装、相机、串口、算法与输出参数 |
| `main.py` | 相机初始化、亮度调节、取帧与主循环 |
| `comm.py` | MAVLink 解析、数据流协商、时钟同步、缓存与发送 |
| `algorithm.py` | 特征、稀疏去畸变、地面投影、二维平移 RANSAC |
| `control.py` | 姿态/高度有效性、关键帧、失跟恢复与状态 |
| `output.py` | 正式位姿摘要、ODOMETRY 发布准入 |
| `test.py` | 模式 1 详细诊断；模式 2 采图基线与完整流程 FPS 测量 |

将七个 `.py` 文件一起复制到 OpenMV 同一目录。正常运行 `main.py`；诊断或测速运行 `test.py`。更新时完整替换七个文件，避免新旧接口混用。README 留在电脑上即可。不要与其他项目的同名 `config.py` 混放。

## 默认输出

运行 `main.py`，每秒最多两条位姿摘要；不绘图，不加载测试模块，不采集测试阶段计时。示例仅说明格式：

```text
状态=跟踪正常（近似） | N=+0.123 E=-0.045 m | 高度=0.803 m | 横滚/俯仰/航向=+1.2/-0.8/+32.5 度 | FPS=19.0 | 质量=35/100
状态=角点不足（近似） | 位置=无效 | 高度=0.803 m | 横滚/俯仰/航向=+1.2/-0.8/+32.5 度 | FPS=19.0 | 质量=0/100
```

- N/E 是视觉位置，单位米，方向随飞控姿态参考系；原点在初始参考图建立时确定，正常换关键帧不改变原点。
- 高度是机体参考点到水平地面的垂直距离，经过 ToF 倾角与安装偏移补偿。外参未知时为近似值。它不是 NED 的 Z；本程序不估计视觉垂直位置，因此省去固定无效的 Z 字段。
- 横滚/俯仰/航向来自飞控，单位度。`--` 表示当前数据不可用。
- “位置=无效”不会显示上一次位置；质量为工程评分，不是正确概率。
- FPS 是实际主循环统计，包含采图、通信、等待、计算和打印。`TARGET_FPS=30` 是算法预算目标，不保证实机达到 30 FPS。

摘要限频只影响显示。ODOMETRY 发布准入和失效取消仍逐帧执行。

## 首次运行

1. 确认 ToF 在 QGroundControl 中有正常测距，相机向下、地面清晰。先用带随机纹理的平面验证。
2. OpenMV 与飞控 TX/RX 交叉并共地，两端波特率一致。默认 `UART_ID=3`、`BAUDRATE=115200`；引脚与串口实例以实际硬件为准。
3. 当前已验证的飞控链路为 GPS2 对应 `/dev/ttyS6 @115200`，MAVLink 模式为 **Custom**。这是当前接线记录，不适用于所有板卡；用 QGC 的 `mavlink status` 确认设备路径、实际频率和发送预算。原先 Onboard 模式曾造成输出频率被压低。
4. 正常状态应从等待连接、等待同步，进入高度恢复、建立参考图、确认跟踪稳定，再到跟踪正常。初始化期间位置无效是正常的。
5. 默认 `SEND_ODOMETRY=False`，先在桌面或支架上验证位移方向、静止漂移、转动和失效恢复。

## 自动适应与常用参数

| 参数 | 默认值与含义 |
|---|---|
| `CAMERA_AUTO_TUNE` | `True`：每 0.5 秒根据亮度和角速度调曝光、增益；小变化不重复写寄存器 |
| `EXPOSURE_US` / `GAIN_DB` | 启动值 20000 us / 18 dB；软件调节开启后会继续变化 |
| `CAMERA_AUTO_TUNE=False` | 保持配置的曝光/增益；对应值为 `None` 时启用相机自身自动模式 |
| `FEATURE_SCALE` | `0.5`：QVGA 采图，缩至 160×120 提特征；坐标映射回标定尺寸 |
| `FEATURE_DETECTOR` | `auto`：先 FAST，连续缺少角点时尝试 AGAST |
| `FEATURE_ADAPTIVE` | `True`：按角点数量和提取耗时调整下一帧的阈值与数量上限 |
| `MAX_KEYPOINTS` | `48`：特征数量上限，不为补足数量重复处理同一帧 |
| `KEYPOINT_NORMALIZED` | `True`：优先单尺度；与参考帧高度变化大时自动使用多尺度 |
| `STREAM_POLICY` | `auto`：先观察现有数据流，缺失或不足时请求；`listen` 只接收；`request` 主动请求 |
| `ATTITUDE_HZ` / `RANGE_HZ` | `None`：请求目标按 FPS 预算生成；默认预算下约 45 / 30 Hz，实际频率与时间戳取接收数据 |
| `MIN_RANGE_M` / `MAX_RANGE_M` | `None`：采用测距消息报告的量程；填数值可进一步收窄范围 |
| `TOF_SENSOR_ID` | `None`：自动发现；多个下视测距器时须指定实际 ID |
| `DISPLAY_HZ` | `2`：中文摘要频率 |

软件曝光控制优先限制运动模糊：曝光约 2–12 ms，并受 FPS 预算和角速度进一步约束；增益限制在 0–30 dB。启动对焦只执行一次，运行中不连续对焦。若自动对焦失败，会显示一次提示。

`listen` 模式仍保留心跳和时钟同步交互，只是不发送数据流频率请求。程序不会改飞控的模式、串口参数或 EKF 参数。

## test.py：详细诊断与FPS限制测量

正常使用 `main.py`。需要测试时停止当前脚本，在 OpenMV IDE 打开同目录 `test.py` 并运行，只修改该文件顶部的模式：

```python
MODE = 1  # 详细诊断
# 或
MODE = 2  # 测量FPS限制原因
```

不再通过配置调试开关切换输出。两个入口复用同一主循环、算法与输入健康检查；测试不会提高分辨率、修改特征缩放或放宽定位门槛。测试期间始终禁止发布ODOMETRY；心跳、时间同步和现有消息流请求仍正常运行。正式入口继续使用 `SEND_ODOMETRY` 和全部发布准入条件。

### 模式1：详细输出

默认每秒一组：位姿摘要、连接/同步、姿态与测距频率及接收年龄、图像与最新姿态的时间差、同步RTT/样本数/拒绝数、CRC错误、请求结果、原始ToF距离/量程/信号质量/传感器ID、高度处理状态、跳过旧测距数，以及真实特征数、检测器、实际阈值、数量上限、工作图大小、单/多尺度、匹配/内点、覆盖格数、分散度、几何残差、关键帧与重置计数、曝光和增益。

同时输出当前帧采图、等待姿态、缩图、检测与ORB描述子、匹配、去畸变/投影、RANSAC/精化和VO总处理耗时。未执行的阶段显示“未执行”，不是0ms。`find_keypoints()`为原生组合接口，所以只报告“检测+ORB描述子”合计。相机寄存器仅在低频详细输出或亮度调节时读取，主入口不为诊断额外读取。

详细打印会降低本模式FPS；查看性能请用模式2。持续运行模式1时在IDE停止即可。

### 模式2：自动测速

1. 先测3秒采图基线，包含同一亮度调节，记录实际新图像频率、snapshot耗时和曝光。
2. 运行真实完整链路预热5秒，等待连接、时间同步与自适应。
3. 连续测量15秒；保留正式位姿摘要及其输出成本，不逐帧打印测速明细。
4. 集中输出报告并退出。时长可在 `test.py` 顶部调整。若预热结束仍未同步，报告会保留真实等待状态，不伪造姿态或有效位置。

报告包含新图像Hz、有效定位Hz、有效率、完整循环超预算次数、阶段执行次数、平均/P50/P95/最大耗时、阶段时间占比、失败状态分布、耗时前三项及排查线索。覆盖采图前后通信/同步、snapshot等待、姿态等待、曝光调节/统计、VO总处理及其子项、循环维护、GC和正式摘要输出。样本使用固定容量整数数组；默认P50/P95覆盖各阶段最近最多256次执行，平均/最大值覆盖全部测量样本。测试自身计时和采样有额外开销，另报告统计管理/未分项间隙。

VO总处理包含其子项，循环维护包含GC，父子项不能重复相加。占比用于判断循环时间花在哪里，采图等待和通信等待不能当成CPU计算占用。阶段均值只对该阶段实际执行的样本统计，不能直接相加当作整帧均值。循环总耗时直接测量，不由阶段分位数相加。

先在当前地面测一次，再在可稳定跟踪的纹理平面测一次。如果一直角点不足，匹配、投影或拟合可能没有执行；该次数据不能代表正常跟踪时的完整负载。正常纹理用于覆盖后半段测试，不要求比赛场地铺标准光流网格。

测速期间保持高度、光照和场景尽量一致；比较基线与完整流程时也核对曝光变化。分别对照IDE图像预览开启和关闭的运行结果。采图占比大不直接证明传感器硬限速：相机读出、单缓冲错过帧和循环调度都可能增加snapshot等待；本测试不自动改缓冲与图像时间戳。

原始距离合格不代表高度已有效，姿态缺失或恢复样本不足时高度仍须等待。消息频率按接收消息的测量时间戳统计；断流后可能保留上次频率，应结合当前接收年龄、连接与同步状态判断。

## 常见状态

| 状态 | 含义与检查方法 |
|---|---|
| 等待飞控连接 | 检查供电、共地、TX/RX、串口与波特率 |
| 等待时钟同步 | 检查双向通信、TIMESYNC 往返时间；不能只确认有接收 |
| 等待图像时刻的姿态 | 检查姿态实际频率、时间对齐及串口拥塞 |
| 测距无效 | 根据中文细分原因检查距离、量程和信号；质量字段 0 表示未知，不直接当作无效 |
| 测距缺少对应姿态 | 旧测距没有可用姿态；程序会跳过无法补齐的旧样本，继续处理新样本 |
| 确认测距稳定 / 确认跟踪稳定 | 等待连续有效样本，默认各 3 次 |
| 画面纹理不足 / 角点不足 | 检查曝光、对焦和地面纹理 |
| 特征主要在一条线上 / 过于集中 | 单条瓷砖边缘不足以可靠约束二维位置；增加分散的角点和纹理 |
| 跟踪丢失 | 当前图像不能与参考图可靠匹配，尝试回到旧视野并减小运动 |
| 倾角或转速过大 / 振动超限 | 降低运动或检查机械安装 |

纯色地板即使曝光正常，也可能无法提供可靠的 X/Y。精简代码可以减少开销，无法恢复图像中没有的信息。先铺随机纹理纸、杂志等静止平面排除环境因素。

建立有效轨迹后失跟，会保留原关键帧尝试重定位，不把未知运动绑定到旧位置。仅在尚未形成有效轨迹、初始参考图连续匹配失败时重建初始原点。无法恢复时重启脚本，或由自己的调度调用 `controller.reset()`；飞控重启、时钟映射跳变和姿态参考跳变也会触发重置。普通换关键帧不增加 `reset_counter`。

## 标定与输出准入

图像尺寸为 320×240，已填入原始内参与五个畸变系数，仅对稀疏匹配点去畸变。改变分辨率、镜像、翻转或镜头状态后需重新核对标定。

坐标：机体系 B 为前/右/下；相机系 C 为图像右/图像下/光轴前。默认下视安装为画面上方对应机头、画面右方对应机体右，`R_BC` 为：

```text
 0 -1  0
 1  0  0
 0  0  1
```

以下参数需要实测确认：

```python
CAMERA_POS_B_M = None                # 机体参考点到相机光心，前/右/下，米
TOF_POS_B_M = None                   # 机体参考点到ToF测距原点，前/右/下，米
CAMERA_ORIENTATION_CONFIRMED = False
SENSOR_TIMING_CONFIRMED = False
```

未知值 `None` 不代表已标定的零。默认允许共点近似，标“近似”、质量上限 35，禁止回传有效 ODOMETRY。禁用 `ALLOW_APPROXIMATE_EXTRINSICS` 后会等待安装参数。

回传需同时满足：外参和方向已确认，曝光/传感器延迟已标定，连接及同步正常，高度和当前视觉位置有效，质量达标，并显式开启 `SEND_ODOMETRY`。默认只做水平位置：ODOMETRY 使用 LOCAL_NED，z 为有限零占位且方差很大，姿态/速度/角速度为 NaN。飞控融合项须另行配置并验证，本程序不会自动开启融合。

ODOMETRY 使用 OpenMV 的本地采集时间，由飞控同步转换，不能预先转换后再重复转换。`snapshot_return` 和 `frame_callback` 都不是天然准确的曝光中点，需实测 `CAMERA_TIME_OFFSET_US` 及姿态、测距延迟；仅将开关改为 True 不等于完成标定。

## 验证范围

代码已做 PC 回归检查，覆盖几何、缩放坐标、时间同步、测距队列、失跟恢复、MAVLink 分包/噪声/CRC、无效观测停止发布，以及入口分工、阶段计时、固定容量统计和日志限频。PC 检查不能证明 OpenMV 实机 FPS、精度或飞行稳定性。

上板后依次验证：静止、已知距离 N/E 平移、原地旋转、升降、关键帧续接、遮挡恢复、ToF 断流和突变。保持地面近似水平且静止；单点 ToF 无法保证识别台阶或坡度。
